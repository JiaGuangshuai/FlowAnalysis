# FlowAnalysis：跨平台流式细胞分析软件设计草案

日期：2026-09-06。保留最初分期设计。用户随后已批准开发，要求全部进阶功能纳入首版实现；当前实现与实测结果以 README 和 VALIDATION.md 为准。完整分发许可已调整为 GPL-3.0-only。

用户目标：个人科研使用，免费开源，在 GitHub 发布，提供 macOS 与 Windows 安装包及中英文界面。用户已明确：常规流式与原始光谱流式两类均需要。

## 1. 产品范围与分期

采用同一套源码与分析核心，分别打包两个平台，项目文件互通。优先规划 Apple Silicon Mac 与 Windows x64；Intel Mac 作为独立构建目标，具体最低系统版本和支持架构在依赖打包验证后确定。软件完全本地分析，无需账号。公开仓库发布源码、安装包和许可允许的示例数据；用户实验数据保留本地。

以 FlowJo 常见工作流程作为功能参照，界面和代码独立设计。完整对标范围比手动圈门大：还涉及光谱解混、细胞周期、增殖、动力学、插件等。分阶段实现不能表述为已经达到所有版本及插件的完全等价。

| 功能 | A：常规分析测试版 | B：双流程正式版 v1.0 | C：进阶扩展 |
|---|---|---|---|
| FCS 2.0 / 3.0 / 3.1 导入、通道与样本元数据 | 完成并验证 | 扩充仪器样本覆盖 | 非标准文件适配 |
| 散点、伪彩密度、等高线、直方图、叠加 | 核心图形 | 全部完善 | 更多展示方式 |
| 矩形、多边形、椭圆、区间、象限、布尔门 | 完成并验证 | 反向门控、批量复核 | 自动门控 |
| 常规补偿：导入矩阵、单染对照估算、人工检查 | 完成并验证 | 完善 QC 与版本管理 | 额外稳健估计方法 |
| 已解混 FCS 导入与分析 | 完成并验证 | 完善处理状态提示 | 更多仪器兼容 |
| 原始光谱 FCS 解混、参考谱、单一 AF 成分 | 预留接口与数据验证 | 必须完成目标仪器验证 | 多 AF 成分、加权等算法 |
| 计数、父群体比例、总比例、均值、中位数 | 完成并验证 | 可配置统计表与批量导出 | 扩充统计量 |

| 图版排版、PDF/SVG/PNG、CSV/XLSX、子群 FCS 导出 | 基础导出 | 完整常规工作流 | 更多图版模板 |

| 细胞周期、增殖、动力学、派生参数、板布局 | 暂不实施 | 接口预留 | 逐项设计与验证 |

B 阶段包含原始光谱解混，不能仅完成 A 阶段就宣称满足用户完整需求。C 阶段保留在完整对标路线中；每个模型须单独验证，不承诺复制专有算法或插件接口。FlowJo v11 工作区兼容性单独评估，不由 v10 支持推断。

## 2. 信息结构与界面

主导航：项目 / 分析工作台 / 补偿 / 光谱解混 / 统计表 / 图版排版 / 设置。界面示意为了便于预览，将统计与导出合并为一页；正式桌面版分离统计表和图版。

分析工作台采用可拖动分隔的三栏加底部状态栏：

- 左栏：样本组、样本、门控树，支持多选、查找、重命名、拖动模板与组内应用。明确区分共享模板和样本独立调整。
- 中栏：当前样本和父群体路径，绘图区、X/Y 通道、变换与图形设置、画门工具。支持单图放大及 2×2 联动视图。双击群体进入下一级；门顶点可调整；编辑显示预览，确认后触发正式计算。
- 右栏：门名称与定义、父群体、计数、百分比、统计通道、补偿或解混方案、变换参数、修改影响范围。
- 底栏：后台任务、全量统计状态、显示抽样数量、异常和保存状态。计算未完成时标为“计算中”，不把旧结果当作当前结果显示。

项目页：新建、打开、最近项目、导入 FCS、导入工作区。拖入目录先预览样本清单、重复文件及通道差异，再写入项目。

补偿页：选择样本与对照 → 指定单染通道 → 检查正负群 → 预览溢出矩阵及补偿前后图 → 应用到指定样本。矩阵明确行列语义、单位、通道 ID 和版本；修改矩阵后标记下游门和统计需要重算。

光谱解混页：确认原始检测通道及仪器设置 → 分配单染和未染对照 → 检查参考谱 → 设置自发荧光成分 → 解混预览 → 质量检查 → 全量应用。显示参考谱曲线、通道映射、谱间相似性、矩阵秩/条件数、重建残差和解混后双参数图；避免把单个数值称为“质量合格”的唯一依据。

统计页：行选择样本/群体，列选择统计量/通道；始终显示百分比分母。导出同时记录完整门路径、处理方案 ID、统计数据空间、软件版本。中位数与算术平均数分开命名，不使用含义不明的单独“MFI”标题。

图版页：左侧图形列表、中间页面画布、右侧字体/轴/尺寸设置；拖放、对齐、统一样式、叠加样本、批量套用。图版引用门与绘图配置，不把屏幕截图作为唯一输出。

中英文：菜单、工具提示、报错、帮助、首次使用引导均走翻译资源；语言切换不改变样本名、marker、通道 ID、门 ID 或分析结果。导出语言可独立选择。支持 Unicode 文件路径；数字序列化采用固定规则。Mac 使用 Command 快捷键，Windows 使用 Ctrl。

## 3. 技术方案

首选 Python + PySide6 / Qt Widgets + PyQtGraph。科学计算使用 NumPy / SciPy、FlowIO / FlowUtils / FlowKit；出版图形使用 Matplotlib。使用 Qt 布局、树模型与可停靠面板，独立开发门编辑器和图版编辑器。PyQtGraph 是绘图候选，门的数学判定仍由分析核心执行。

理由：常规流式的读写、变换与门控有现成开源基础，Python 与后续降维和聚类衔接直接；Qt 适合桌面文件操作、长任务和复杂树表。界面与算法分离，性能热点经基准测试后才决定是否迁移到编译扩展。

FlowKit 可提供 FCS、补偿、变换、标准门和部分工作区解析；光谱参考谱构建、解混求解、质量检查和仪器适配由独立模块承担，不能把安装 FlowKit 等同于已经有完整光谱平台。

```text
桌面界面：项目、样本树、门编辑器、补偿、解混、图版、中英文
                    ↓ 命令与带版本的状态更新
应用服务：撤销重做、任务队列、模板应用、自动保存、导出
                    ↓
分析核心：FCS → 补偿 / 光谱解混 / 已处理数据 → 变换 → 门树 → 统计
                    ↓
存储层：项目清单、原始数据引用、处理配置、结果缓存、历史记录
```

拟定源码职责：`ui/` 界面，`application/` 用例与任务，`core/io/` 文件适配，`core/compensation/` 常规补偿，`core/unmixing/` 光谱，`core/transforms/` 变换，`core/gating/` 门树，`core/statistics/` 描述统计，`storage/` 项目与缓存，`export/` 导出，`i18n/` 翻译，`tests/` 测试，`packaging/` 打包，`docs/` 文档。以上是结构设计，尚未创建这些应用模块。

## 4. 数据处理与结果可复现

为每个样本保留不可变原始事件和稳定事件索引。数据状态分别记录 raw-conventional、compensated、raw-spectral、unmixed、unknown；结合元数据与用户确认，不仅凭文件名判断。unknown 不自动套用补偿或解混。已处理数据不自动重复处理。

常规流程：原始线性检测信号 → 通道顺序校验 → 溢出矩阵求解 → 变换坐标 → 门控。光谱流程：原始线性检测信号与对照 → 参考谱模型 → 解混 → 派生荧光参数 → 变换 → 门控。保留散射、时间等非荧光通道。

光谱初始算法采用可解释的线性最小二乘基线，以 QR/SVD 求解和秩诊断代替直接求逆；定义模型 y ≈ R·a + b，明确参考谱归一化、背景 b、成分幅值单位及 AF 是否作为 R 的独立列。具体背景策略须用目标仪器数据验证，避免先减掉 AF 又作为成分重复估计。加权最小二乘等方法作为可版本化扩展。保留负值，不在默认流程截断为零。

参考输入需要原始检测器通道、每种荧光的单染参考、适配的未染对照或经过验证的参考谱。记录采集设置、控制类型、阳性/阴性门、染料与通道映射。缺失检测器或参考、秩不足、明显设置不一致时阻止盲目求解，并列出具体缺项。不会从仅含已解混参数的 FCS 声称恢复原始检测信号。

变换支持 linear、log、Logicle、biexponential、arcsinh；参数与版本都存档。不把 Logicle 与所有 biexponential 实现当作完全相同。

门存储稳定 UUID、父门、门类型、坐标空间、通道 ID、变换 ID、顶点/阈值、布尔引用和边界包含规则。布尔门求补的范围明确为其指定父群体。几何判定先与父群体掩码相交。修改补偿、解混或变换后按依赖关系使缓存失效；变换变化需明示门如何迁移，不能悄悄改变语义。

统计默认使用全量门内事件，均值/中位数默认在补偿或解混后的线性强度空间计算，界面明确数据空间。空群体强度统计为 NA，父群体为空时百分比为 NA。几何均值遇到非正值不偷偷加常数。计数、父比例、总比例定义固定；显示抽样不影响统计。

大数据策略：按样本排队、按通道取数、密度栅格或确定性抽样显示、计算结果和门掩码缓存。耗时计算放工作进程，支持进度和取消；消息附项目/样本/配置版本，丢弃过期结果。是否直接使用 FlowKit 全量内存路径或增加分块适配，由性能基准决定。

项目使用带 schema 版本的开放清单与本地缓存：manifest、样本校验和与相对路径、通道映射、处理方案、门树、图版、软件/依赖版本和编辑记录。默认引用原始 FCS，可选制作包含 FCS 的可移植项目包；缓存可删且可重算。原子保存、自动保存、崩溃恢复及文件搬迁后重新定位都纳入设计。

## 5. 验收，不只检查能否画图

| 项目 | 验证方法与通过原则 |
|---|---|
| FCS 读取 | 公开测试样本与授权真实样本，检查事件数、通道名/ID、元数据、数值、字节序与异常文件；拒绝静默修复未知格式 |
| 补偿与变换 | 合成已知矩阵、已知输入输出及独立参考实现；检查正负值、顺序、单位和数值精度 |
| 光谱解混 | 已知混合物回收、噪声/近共线谱/秩不足测试；再用目标仪器原始文件与厂家解混输出比较分布、残差、群体分离和统计。算法不同不预设逐事件完全一致 |
| 门与比例 | 固定门和处理条件下检查事件归属；非边界测试事件精确匹配，边界归属规则固定。与参考软件的差异逐项归因 |
| 真实工作流 | 导入 → 对照指定 → 补偿或解混 → 多层门 → 批量应用 → 图表导出 → 保存重开，结果可复现 |
| 项目与模板 | 文件移动、中文路径、重复名称、样本缺通道、矩阵版本变化、取消任务和崩溃恢复 |
| 性能 | 在注明硬件与内存的环境测试 10 万、100 万、500 万事件和不同通道数；首个参考目标是 16 GB 机器上单样本百万级分析可用。记录耗时和内存，不把目标当作已测结果 |
| 双平台 | 在 Mac 与 Windows 分别构建并验证安装、启动、导入、交互、导出和项目重开；同一固定分析项目输出在预先规定的数值容差内一致 |
| 语言与图形 | 两种语言、字体/DPI、导出字体和轴标签均检查；所有可见模拟内容与真实结果明确区分 |

数值容差按操作、数据类型和参考值规模分别确定并在测试规格中固定，不能为了通过而事后放宽。真实分析参考可使用用户已有的合法导出结果；不要求必须购买 FlowJo 才能使用本软件。

## 6. 发布方案

GitHub 仓库建议名暂为 `FlowAnalysis`，归属账号与最终名称待用户提供。拟采用 BSD-3-Clause 作为自有代码许可；打包依赖保留各自许可、版权、源码获取与必要的替换/重新链接说明，具体 Qt 模块和分发方式在打包时逐项核对。项目自有许可证不覆盖第三方库。

建立中英文 README、入门指南、数据流程说明、已验证仪器列表、兼容性限制、变更日志、贡献指南、第三方依赖清单和问题模板。示例只放合成数据或可再分发的公开数据；个人实验原始数据默认忽略。

使用 GitHub Actions 在各目标操作系统构建并运行检查，发布 macOS `.app`/`.dmg` 和 Windows `.exe` 安装版或便携目录包。PyInstaller 可作为冻结候选；不是在 Mac 上直接生成所有系统可运行的包。锁定依赖，记录构建环境和产物校验和。正式签名/公证单独配置用户持有的证书；是否具备签名证书不影响先开展源码与测试包开发。

## 7. 批准后开发顺序

1. 建立项目骨架、中英文框架、依赖锁和双平台最小打包验证；同时核查真实常规/光谱 FCS 与对照文件的可读性。
2. 打通常规分析端到端流程、数值测试、门交互和保存，交付 A 测试版。
3. 完成光谱参考谱、解混与 QC，加入目标仪器验证，完成图版/统计/兼容支持，交付 B 双流程正式版。
4. 继续 C 进阶功能；每个算法单独定义参数、解释、测试和可复现要求。

批准项：三栏工作台与独立光谱模块；同源码双平台；本地离线和中英文；A→B→C 路线且 B 必须包含原始光谱解混；Python/Qt 为首选技术栈；GitHub 开源分发。仪器型号、机器架构、实际文件规模和 GitHub 归属可以在后续补充，不妨碍审阅当前设计。
